# Deep Review — 2026-07-19

Reviewed as (a) a bulk buyer in Dubai/Gulf placing a first container order, and
(b) the seller in Cumilla running the trade desk. Method: headless drives at
390 / 768 / 1440–1536px, full CTA + filter + modal + form probes, payload and
meta audit, live-Firestore data pass, plus a trust-signal walk of every section.
Facts found by measurement are marked ●; judgment calls are marked ○.

## A. Trustworthiness — what a Gulf buyer checks before replying (1–14)

1. ● Certifications (ISO, HACCP, Halal…) are badges only — no certificate
   numbers, issuing bodies, or PDFs. For Gulf buyers **Halal must name its
   certifying authority**. Add a "Verified documents" row with scans on request.
2. ○ No trade license / BIN / export registration number anywhere. One footer
   line ("Export Reg. No. …, Cumilla, Bangladesh") reads as legitimacy.
3. ○ No human faces. B2B buyers fear faceless trading houses — add the MD's
   photo + a short signed note in About, and a team/warehouse photo when ready.
4. ○ No buyer references, testimonial, or shipment track record ("120+
   containers shipped since 2023 · Jebel Ali, Dammam, Doha").
5. ○ No office/warehouse/packing-line photography — the strongest possible
   trust signal for a commodity exporter (client to supply).
6. ● Contact email is `@gmail.com` while the canonical domain is
   sabaglobalventures.com — get the domain live and use info@ / trade@.
   A Gmail trade desk is the #1 credibility leak.
7. ○ Payment terms absent. State accepted instruments (Irrevocable LC at
   sight, TT with advance) — buyers pre-filter on this.
8. ○ Sample policy absent ("Samples free, buyer pays courier") — standard ask.
9. ○ Lead times absent (e.g. "FCL in 2–3 weeks from confirmed order").
10. ○ Port facts are prose only. A structured "Trade facts" strip: Port of
    loading Chattogram · Air Dhaka · Incoterms FOB/CIF/CFR · Docs: CoO, Halal,
    Phyto, Health.
11. ● "We reply fast" is unquantified — promise "within 24 hours (GMT+6)".
12. ○ No downloadable **line-card PDF** — Gulf procurement forwards PDFs
    internally; a one-page branded PDF multiplies reach.
13. ● JSON-LD exists (Organization) but no per-product `Product` structured
    data — rich results build third-party legitimacy.
14. ○ An "As seen at" row (trade fairs: Gulfood, exhibitions) once available.

## B. Buying workflow & functionality (15–27)

15. ● Contact form has **no `required` attributes / native validation** —
    verify contact.js blocks empty submits; add required + inline errors so an
    empty WhatsApp message can never open.
16. ● Form lacks the buyer's own phone/email field — if the WhatsApp handoff
    fails (desktop without WA), the inquiry is lost. Capture a reply channel.
17. ● No submit confirmation state — after the WA window opens, show "Your
    inquiry is drafted in WhatsApp — press send there" so buyers know status.
18. ● Unset social links render as dead `#` links (footer + menu IG/FB/in) —
    spec says unset socials hide; they currently don't.
19. ● Live catalogue references three missing photos (`hilsa-ilish.jpg`,
    `table-potato.jpg`, `green-chilli.jpg` → HTTP 404) — re-upload via Admin
    or commit the files.
20. ● No per-product deep link (e.g. `#product=miniket-rice`) — buyers can't
    share one SKU with a colleague; modal state is unshareable.
21. ○ No catalogue search box — 20+ SKUs and growing; a buyer looking for
    "chinigura" shouldn't scroll.
22. ○ Product modal: single image, no gallery/zoom — bulk buyers inspect
    grain length, shrimp glaze, packaging closeups.
23. ○ MOQ hidden until modal — put a small "MOQ 1×20' FCL" chip on each card.
24. ○ No unit-of-sale clarity on cards (per MT? per FCL?) — one line fixes it.
25. ● "Prefer Email?" path: confirm the drafted email carries the full form
    summary (WhatsApp path does).
26. ○ Add `tel:` click-to-call prominently for Gulf daytime callers (exists in
    contact card only).
27. ○ Admin: inquiries stored locally/Firestore but no email/WhatsApp
    notification to the owner on new inquiry — add a cloud function or at
    least a daily check habit documented in Admin.

## C. Design, responsiveness, accessibility (28–39)

28. ● Placeholder captions truncate mid-word ("…at a Bangladesh…",
    "…ground turmeri…") — shorten alt strings or widen the cartouche.
29. ● Mobile featured deck: three cards squeezed side-by-side (~120px each) —
    make it a snap-scroll row of full-width cards.
30. ● Mobile catalogue is a 12,600px column (20 stacked cards) — batch with
    "Show more" (8 at a time) or restore a compact 2-up mobile card.
31. ● 35 text elements render below 11px (eyebrows, captions, side-rails) —
    raise the floor to ~11.5px; luxury is never squinting.
32. ● Mobile: floating dock bubbles overlap the market ticker's right edge —
    add right padding to the marquee or float the dock lower.
33. ● Tablet (768): banner subtitle brushes the paddy-stalk art — add left
    padding at the 700–900px range.
34. ○ Hero portal on mobile is a 0.28-opacity backdrop — the nouka engraving
    is invisible on phones; consider a small full-opacity portal between title
    and CTAs on mobile.
35. ● Dead CSS: the old two-up mobile card rules (`.product-card .body`, etc.)
    target classes that no longer exist — remove.
36. ○ Arabic/RTL: Gulf market with EN-only site — plan an AR toggle (layout is
    flex/grid, mostly RTL-safe; needs `dir` handling + Arabic serif pairing).
37. ○ Keyboard path: modal opens on card click — ensure Enter/Space on a
    focused card opens it and focus is trapped inside the modal (check).
38. ○ `prefers-contrast: more` — gold-on-navy hairlines (.22 alpha) vanish for
    low-vision users; add a contrast-more override thickening lines.
39. ○ Print stylesheet: buyers print/PDF pages for files — a minimal print CSS
    (white bg, black text, no art) makes the site file-able.

## D. Performance (40–45)

40. ● Page weight 5.15MB. The golden engravings alone: tiger-gold 1.32MB,
    fisherman-cut 1.06MB, rickshaw-cut 690KB, shapla-cut 333KB, sampan-cut
    247KB — convert to WebP/AVIF at display size (expect 70–85% saving).
41. ● Side-accent rasters all load at page-open even 10k px below the fold —
    gate their `background-image` behind the existing IntersectionObserver.
42. ● Client-uploaded photos live as base64 data-URLs inside Firestore docs
    (140KB+ per doc read) — move to Firebase Storage URLs; catalogue reads
    will get dramatically lighter.
43. ● `emblem.svg` and `favicon.svg` are ~59KB each — optimize (likely traced
    art; SVGO or re-export flat paths).
44. ○ Fonts: preload the two critical weights (Cormorant 500/600) and
    `font-display: swap` — check for FOUT on 3G.
45. ○ Add explicit `width`/`height` (or aspect-ratio) to card/modal images to
    remove any CLS during catalogue render.

## E. SEO, growth, operations (46–50)

46. ● `og:image` is a relative path — WhatsApp/LinkedIn link previews (your
    main sales channel!) need an absolute URL, and ideally a 1200×630 card
    with the paddy banner + wordmark.
47. ● No analytics — add GA4 or Plausible + outbound-click events on every
    `wa.me` link so the seller sees which products drive inquiries.
48. ● Domain + hosting: enable GitHub Pages, map sabaglobalventures.com
    (canonical already points there), add the domain to Firebase Auth
    authorized domains, and pick www vs apex once.
49. ○ Per-product `Product` JSON-LD + a `FAQPage` block (MOQ? payment? ports?)
    — the FAQ also answers buyers' first three WhatsApp questions before they
    ask.
50. ○ Content cadence for legitimacy: a tiny "Season notes" line (e.g. "Aman
    harvest arriving — new-crop Miniket booking now") updated monthly via
    Admin proves the house is alive — dead sites lose Gulf buyers instantly.
